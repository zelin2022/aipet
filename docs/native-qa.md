# Native Windows desktop checks

Run `npm run test:native` (or `node scripts/test-native.mjs`) for the isolated Windows x64 checks. This test briefly displays its own pet and a near-transparent blank fixture. Its own fixture is briefly focused/fullscreen to exercise the real foreground helper. No global mouse click or keyboard input is generated, and no existing user application is explicitly activated, closed or controlled.

## Scope

The harness starts a separate TEST `--background` application with a newly created temporary preferences/inbox directory. It never installs AI hooks or modifies startup registration, AI configuration, production preferences or another Aipet instance. It closes only its own windows and helper process, then removes its checked temporary directory. Native probe output contains only comparisons with the known owned window handles; it does not expose other windows' handles, titles, command lines, text or screenshots.

For input routing, the test supplies synthetic Claude and Codex process presence so both original characters appear side by side inside the same pet window. Its blank fixture is sized from the pet's actual native bounds and sits beneath it at known coordinates. The test reads source alpha separately from each bundled original sprite to choose an opaque point and sends synthetic mouse movement only to its own Electron renderer. This exercises the real source-alpha hit test and narrow IPC path that toggles native click-through. It then calls Windows `WindowFromPoint` and compares the resulting root window with the two known owned windows: opaque Claude and ChatGPT artwork should each hit the pet; the transparent gap between them and a transparent corner should hit the blank fixture. Each provider's result is reported separately. This checks real OS hit-test targets, rather than merely asserting that the application called `setIgnoreMouseEvents`. It does not send a global click. Microsoft's [WindowFromPoint reference](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-windowfrompoint) describes this point query.

For fullscreen behavior, the test starts the project's fixed independent foreground helper. With only its own blank fixture deliberately focused, it checks windowed → fullscreen → windowed metadata and verifies that the reported fullscreen rectangle matches that fixture's monitor. A separate narrow native probe confirms that the fixture really owns foreground focus. Focus protection or an unavailable probe produces an inconclusive result rather than bypassing Windows restrictions. The fixture is about 2% opaque to keep its brief display unobtrusive. It is destroyed afterward; Windows handles normal focus restoration without the harness activating another application.

Coordinates are converted through Electron's `screen.dipToScreenPoint` for native physical queries and `screen.screenToDipRect` for helper geometry. Each available monitor is tested at its actual scale factor. The report records monitor count, scale factors and work areas. Mixed-DPI coverage is claimed only when monitors with differing scale factors are actually available. See Electron's [screen API](https://www.electronjs.org/docs/latest/api/screen).

The recovery check moves only the test pet outside the visible desktop, invokes the application's actual display-metrics handler with a synthetic event, then checks its real native bounds against current display work areas. Physical monitor unplug/reconnect is not performed. Native dragging, global click delivery and a real Windows login are outside this harness; they must not be inferred from a passed hit-test check.

## Results

The initial single-companion run on 2026-10-23 passed on the available 2,560 × 1,440 monitor at 100% scale. Windows hit-testing returned the pet over opaque artwork and the owned blank fixture over a transparent corner. The offscreen window recovered into the current work area. The native probe confirmed that the owned foreground fixture covered its monitor; the real helper reported a matching fullscreen rectangle and cleared it after the fixture returned to windowed mode. The test began and ended with zero owned BrowserWindows.

The subsequent dual-companion run on the same monitor verified native routing for both original sprites: Claude and ChatGPT each returned `opaqueHitsPet: true`, and both the gap between them and the transparent corner returned the owned blank fixture. Offscreen recovery also passed, with zero owned windows before and after the run. This run's overall result was **inconclusive** because Windows did not give the blank fixture foreground focus. Its native fullscreen transition and monitor coverage were confirmed, but the foreground helper consequently did not report that background window as fullscreen. The harness did not bypass focus restrictions or activate any user application. This fresh focus limitation does not invalidate the successful dual hit-target checks or establish a fresh fullscreen pass. Full details of the most recent run are in the ignored local artifact `out/native-qa.json`.

An initial run was inconclusive because the first QA fixture was non-resizable and did not produce fullscreen metadata. Making the test fixture resizable/fullscreenable and checking actual native monitor coverage resolved that test-fixture limitation. The application and foreground helper were unchanged. A single focused rerun then passed. Multiple monitors, differing scale factors and physical display unplug behavior remain unverified on this machine.

A passed result requires opaque native hit targets for both providers, transparent gap/corner targets, display recovery, matching actual fullscreen metadata, and zero owned windows after cleanup. Inconclusive native probes/focus restrictions are recorded separately and return exit code 2. Actual failed assertions return exit code 1; passed checks return 0. The process has an internal deadline below the launcher's 60-second deadline so it can stop its owned helper and windows before exiting.

Multiple or mixed-DPI monitors and physical unplug behavior remain explicit limitations; they cannot be inferred from the available single-monitor checks.
