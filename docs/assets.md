# CrossPet character assets

The Windows application bundles only the base **Claude** and **GPT** characters for Claude Code and Codex. The importer copies artwork and declarative character data from [CrossPet](https://github.com/lokicorvus/crosspet) at commit `6e98970f6ff9b44e8ac85215241cabcd78f67d92`. It reads files and parses JSON; it does not load upstream modules, run scripts, install hooks, start CrossPet, use its plugins, or run its updater.

## Inventory and quality

| Character | Original images | Original data files | Provider in our app |
| --- | ---: | ---: | --- |
| Claude | 57 WebP images | 1 `character.json` | `claude` |
| GPT | 62 WebP images | 1 `character.json` | `codex` |

There are **119 images**, **2 character JSON files**, and **2 complete upstream license files**, totaling **11,672,443 bytes** before the generated manifest and provenance. Skins, cameo characters, other providers, promotional images, and upstream application icons are excluded.

All selected artwork files are static WebP images, 640 pixels high with varying widths. No image has been resized, recompressed, recolored, redrawn, or cropped. Preserve aspect ratio and bottom alignment in the renderer. CrossPet's moving activity effects are application rendering code, not pre-rendered animation assets; our companion supplies its own motion and activity effects around the original poses. Pose variants and the original blink image are available for independently implemented animation.

## Runtime manifest

`assets/crosspet/manifest.json` is generated by our importer. Its `characters` array contains `id`, `name`, `provider`, `accent`, `egg`, `poses`, `poseVariants`, and `sourceData`. Every image path is relative to `assets/crosspet/`. Only local file paths are present; there are no executable expressions or remote asset URLs.

`poses` includes original filename stems and canonical aliases. For example, Claude's `reading` alias points at the unchanged `characters/claude/reading-2.webp`. `poseVariants.reading` retains the complete ordered list. Variants ending in `-2` or `-3` are alternate pose illustrations, not an assumed frame-timed sequence. `idle-blink` is kept separately from idle variants.

The original JSON files are preserved for provenance and possible dialogue/reference data. They are declarative assets and are not an upstream runtime dependency. Our renderer consumes the normalized manifest. Any future use of dialogue text should treat it as inert strings.

## Reproduce and verify

The reference checkout is development material in ignored `.reference/crosspet/`. The application has no runtime dependency on that checkout. To create it without running CrossPet code:

```powershell
git -c core.hooksPath=NUL clone --depth 1 https://github.com/lokicorvus/crosspet.git .reference/crosspet
```

The importer requires the pinned revision and rejects changed selected source files. If upstream HEAD has advanced, fetch and check out the recorded commit before importing. Do not use upstream installation or integration instructions as part of this process.

```powershell
node scripts/import-assets.mjs
node scripts/import-assets.mjs --verify
```

`--verify` works offline without the reference checkout. It checks all 123 original file hashes and lengths, the normalized manifest hash, pose references, the two-character scope, and unexpected files in the asset tree. `provenance.json` records each upstream source path, local destination, SHA-256 hash, byte count, source repository, and exact commit. Paths in the original data are never executed.

`scripts/import-assets.mjs` belongs to this application. Its import allowlist is limited to the selected character directories, `*.webp`, `character.json`, and the two upstream notices. Unknown selected-directory file types and symbolic links are refused. No dependency installation or network request occurs during import or verification.

## Additional pose artwork

### Selection and timing

The independent renderer chooses from each state's validated pose pool. Claude appends registered custom poses to the imported variants. An activated, complete GPT redesign profile replaces all selected GPT poses together so a pose change cannot switch between costumes. Each provider has its own selection history. Repeated activity snapshots keep the current pose; re-entering a state avoids immediately repeating its previous image. Sustained idle, thinking, reading, coding and tool activity can change pose after 18–26 seconds. Pose rotation preserves the current activity label and does not generate host events. Images decode before they replace the current sprite, and source-alpha hit masks refresh when the image commits.

Idle actions are staggered per provider every 45–75 seconds and last 3.6–4.8 seconds. Their pool uses available humming, stretching, yawning, shy affection, hair-play, looking away with crossed arms, winking, smug expressions and drink-sipping images. Claude drinks black tea from a tiny cup; GPT sips from a white Monster can with a dragon-claw emblem. Puffed cheeks are reserved for two minutes of visible idle time without a local interaction or a fresh activity event, with at least two minutes between repeats. The existing puffed artwork is reused. Petting or poking resets that companion's attention timer; the timer observes no conversations, computer-wide user activity or other apps. Hiding, new activity and Gentler motion also reset it. Any new work cancels idle decoration. A greeting lasts 2.6 seconds on idle appearance/wake. Petting lasts three seconds and returns to the latest activity; a new completion, error or waiting signal takes priority. Gentler motion disables decorative rotations, greetings and idle actions while retaining deliberate interactions. These presentation states never become hook activity metadata.

### Sprite usage counters

**Companion studio → Sprite usage** ranks actual image exposure by display count, visible duration or each character's time share, including zero-use entries. **In rotation** includes the active state pools and matching blink; **All bundled artwork** also shows preserved originals and other images outside the current selection. An image reused by more than one state pool has one aggregate counter. Entering a displayed image counts an exposure; a blink and the return to the resting image are separate exposures. Animation frames and repeated snapshots do not increase its count, and studio previews are excluded.

Time accrues independently for each visible companion, pausing when its pet window is hidden or minimized, Windows locks or suspends, or preview mode replaces normal activity. Window visibility does not establish that other windows leave the sprite unobscured or that the user sees it. Renderer reports renew a maximum five-second lease, so an unresponsive renderer cannot accumulate unlimited time. The bounded local aggregate at `%USERPROFILE%\.aipet\sprite-usage.json` is saved every 30 seconds and on normal quit. It records sprite IDs, content hashes and totals rather than an event history; altered artwork does not inherit another image's totals. There is no reconstruction of earlier usage or automatic pose reweighting. Confirming **Reset sprite counters** starts a fresh period; an image already visible begins its first exposure in that period.

### Custom files

New same-character pose adaptations live separately in `assets/custom/`; imported files and their manifest/provenance remain unchanged. The custom manifest explicitly lists each character, presentation state, PNG, dimensions, prompt, provenance and attribution document. SHA-256 and byte-length pins cover every listed file. Transparent PNGs retain their generated bytes and original alpha channel; the renderer preserves their aspect ratio and bottom alignment.

The main process validates local paths, regular files, hashes, PNG dimensions, alpha-channel headers and corresponding provenance before adding `customPoses` to each character. All custom artwork and its documents share a fixed **128 MiB** byte budget; one PNG is limited to 32 MiB and 16 megapixels. The former 64 MiB aggregate limit was insufficient for thirteen Claude additions plus the complete 38-image GPT redesign. Only validated custom PNGs are permitted as renderer image requests; arbitrary custom documents and filesystem paths are not exposed. This does not execute metadata or generation prompts.

`node scripts/register-custom-assets.mjs` is an explicit development authoring step for approved same-character artwork. Its initial allowlist covers thirteen Claude additions and the complete 37-pose GPT redesign with one matching blink. Separate social-pose allowlists register reviewed `aloof`, `wink`, `smug` and `sip` images when present. Those four presentation states are optional; they do not expand the eighteen required GPT pose states or make an older complete costume invalid. `--enable-gpt` explicitly activates the complete replacement on its first registration; subsequent registrations retain an already activated profile. It records approved filenames and their companion documents in `assets/custom/manifest.json`; it never generates, modifies or recompresses image pixels. A complete candidate is verified before overwriting the previous manifest. Run it after adding or intentionally updating their documents, then run `npm run assets:verify`. Verification still checks all 123 original files and additionally refuses missing, changed, untracked, oversized or linked custom files. It requires no network access.

The registered custom inventory is **57 PNGs: 16 Claude additions plus 41 GPT redesign images**, supplementing the 119 original WebP images for **176 bundled images**. Its complete pinned inventory has 174 files: 57 PNGs, 57 prompts, 57 provenance records, two character attribution documents and the manifest. The 62 original GPT images remain preserved even while the redesign supplies every selected GPT pose. Each character's base coverage has **37 presentation poses plus one matching blink**, followed by four social presentation pools. The social additions reuse Claude's original `proud.webp` for a smug expression and GPT's already-winking `greet-morning-v1.png` through an explicit `wink` alias; neither needs a duplicate generated image. Their existing puffed-cheek images provide the attention-timer response. New images supply both crossed-arms poses, Claude's wink and black tea, and GPT's smug face and white Monster can with a dragon-claw emblem. Reading, coding and running-tool variants join only their corresponding activity pools. None of these presentation choices introduce host activity states or infer that a particular tool ran.

### Complete GPT redesign profile

`profiles.gpt = { "mode": "replace" }` is the sole replacement profile supported by the custom manifest. It activates only after every presentation state and its dedicated `idle-blink` asset validate. Missing states, a missing blink, damaged files, invalid provenance or an incomplete inventory disable the entire GPT replacement at runtime; the complete original GPT set remains the fallback. Valid Claude additions continue to append independently. Strict authoring and packaging checks reject such failures instead of producing a partial profile. `idle-blink` is an image resource only and is never a hook activity, interaction or diagnostic state.

The redesigned GPT base profile reaches Claude's base selected-pose counts:

| Presentation state | Poses per character |
| --- | ---: |
| Idle | 3 |
| Thinking | 4 |
| Reading, coding, running tools | 3 each |
| Waiting | 2 |
| Petting | 4 |
| Greeting | 4 |
| Affectionate idle action | 2 |
| Success, error, sleeping, poking, humming, stretching, yawning, puffed cheeks, hair-play | 1 each |
| Matching idle blink, separate from the pose pools | 1 |
| Optional social actions: looking away, winking, smug expression, sipping | 1 pool each |

The GPT palette retains pearl-white hair and the white/silver interwoven knot ornament while adding amethyst horns, lavender hair shadows, a deeper violet dress and separated dragon features. Its per-image `framing` records integer alpha-content bounds and the original canvas dimensions, matching `output.framing` in the pinned provenance. Renderer framing uses those bounds for consistent desktop scale and interaction geometry without changing the original PNG pixels or alpha. The approved idle concept was reused and 37 new images were generated in seven batches of five or six, each reviewed on light and dark backgrounds at desktop size. The whole reviewed profile was promoted from ignored `out/gpt-staging/gpt/` to `assets/custom/gpt/` and registered together; partial batches were never runtime assets. That initial 51-image custom inventory totaled 96,389,164 pinned bytes. The subsequent six social illustrations were likewise staged and reviewed as transparent generated PNGs before registration, with their own exact prompts, reference hashes and output framing. The aggregate authoring and runtime budget remains 128 MiB.

Packaging copies only this custom manifest's registered images and companion documents and independently verifies the copied custom inventory. The custom artwork remains subject to its recorded source attribution, adaptation terms and upstream rights caveat; it does not acquire the application's code license.
